A. WHAT MASTER DOES, AND WHAT IS LEFT.
   The rescue clauses of a begin with an ensure run in a frame of their own, and an exception no clause takes is held there as its object. At the ensure's entry master makes the exception's object when the raise carried none, for `$!` in the body and for the cause of a raise in the body, and keeps it alive while the body runs (it is pushed on the `$!` stack, which the collector marks, and popped by a cleanup when the body is left). And the catch of each region reads `_excobj = sp_exc_caught_obj();`: where the frame's slot holds no object and a cause waits in sp_pending_cause (a String raise made with `cause:`, or one raised while another exception is being handled), that function makes the object at the catch, with the cause, and stores it in the slot; in every other case it answers the slot.
   So with a cause waiting the region holds an object from the catch on. With none, the exception waits through the body as a class and a RAW MESSAGE in C locals, and after the body master raises by those two, `{ sp_pending_exc_obj = _excobj; sp_raise_cls(_exccls, _excmsg); }`, which copies the raw message first. That message is the one a collection in the body frees; the body's two programs are of that kind, and bare 2b0ebc0a6bfd prints their wrong lines at -O0 to -O3.
   This commit is that remainder and stands on master's rule. The object is master's: made by master's call at master's place and stored where master stores it. The object holds the raw message itself where it held a copy of it, so the raw message lives while the object does. NO SECOND MECHANISM stands beside sp_exc_caught_obj: where master's catch made the object, the entry statement does what master's does. Nothing is raised that master did not raise, and no local of the generated C is assigned: every raise line and every hand-on line of the three regions is master's text, and the entry statement is master's but for the name of the function it calls.

C. WHAT KEEPS THE RAW MESSAGE ALIVE, by the C.
   Through the body: the object is on the `$!` stack (master's `if (_excf) sp_rescue_push(sp_inflight_cause);`), which the collector marks, and sp_exc_gc_scan marks its message, which is the raw message. An exception's message pointer is set where the exception is built and where its `initialize` runs, and neither happens to this object in the body.
   After the body the cleanup gives the `$!` stack back, and nothing holds the object. From there to the next copy nothing allocates: the lines emitted between are the restore of the unwind state, the test for an unwind to resume, and the deferred next, break and return hand-ons. Then one of three.
   (a) The raise, master's line. sp_raise_cls's first statement is sp_msg_heapify, a copy made without a collection, and it roots the copy before anything else. From there it is any raise: the copy is the handler slot's message, and the clause that takes it builds its object with sp_exc_new_for_catch or, for a class of the program with attributes, sp_exc_new_sub_sized, each of which again copies and roots the message before it allocates.
   (b) The hand to an ensure around it. The jump lands before that ensure's entry statement, whose call roots the raw message as its first statement, before the new object is allocated; that object holds it from then on.
   (c) The hand to the region of a synchronize block or of select!'s loop. The region unlocks the mutex or puts the Array back, then raises as in (a). On master the raw message is unmarked at that point too, since the hand popped the slot's frame; nothing is exposed there that was not.
   BY RUN, with allocations between the raise and the read: a class of the program with twelve attributes and no `initialize`, raised by name through two ensures whose bodies enter a begin, make six other exceptions and allocate; the rescue allocates, stores the twelve, allocates again, then reads the sum, the message and the class, three times over. At -O0 and -O2, plain and under SPINEL_GC_STRESS=1 and =2, built default and with --share-strings: this head prints CRuby's lines in all twelve runs; the bare tip has 1 wrong line plain and 3 under stress 2.
