THE FACT, one sentence: the nil seed is emitted only for a class from which
no method of the program can be found, in a program with no finalizer: every
body of the class, and of each parent the program wrote up to the builtin
exception, holds attribute declarations with literal names and nothing
else, and in the whole program every def, and every call by one of
master's by-name words that gives, takes away, hides or renames a method or
evaluates a block, stands in the body of a class or module, outside every
def and block there, with no receiver but self, and no body or assignment
carries the name of Object, BasicObject, Kernel, Module, Class or a builtin
exception.

WHY IT PROVES IT. A method of the program is made by a def or from a block.
(a) A def with no receiver but self, in a class or module body and outside
every def and block, is that class's or module's own (its instance method,
or its singleton's). (b) master's walk has proved, where HE applies at all,
that nothing is named by value and that no module is mixed in
(an include, prepend or extend with an argument that is no literal is a
by-value site), so a module's methods reach no class and no object. (c) The
calls that make a method from a block, or run a block as another object
(define_method, define_singleton_method, the eval and exec families), and
those that take away, hide or rename one, are master's own table
(an_by_name_how: AN_GIVES, AN_GIVES_ALL, AN_RENAMES, AN_VIS, AN_EVAL,
AN_EXEC); HE keeps no word list of its own for them, and `alias` and
`undef` are their node kinds. Each is held to the same place as a def. So
every method of the program belongs to the class or module whose body its
text stands in. (d) From an exception class and its objects CRuby looks
methods up in: the class and its parents (attribute declarations only, so
readers and writers that store what they are given); the builtin
exceptions above, Object, Kernel and BasicObject; and, for the class
itself, Class and Module. A body or an assignment under any of those names
declines the whole program, by the leaf and by `outer::leaf` (`module
Errno; class EAGAIN`). So nothing CRuby calls on its own, by whatever name,
finds a method of the program there.

THE FINALIZER TERM, mine, found after the six roads. A method is not the
only code CRuby runs at a moment of its own: `ObjectSpace.define_finalizer(
"x".dup, proc { e.count = 0 })`, then `GC.start`, then `p e.count` prints 0
on CRuby and on master (whose finalizer has not run yet and whose slot is
zero) and printed nil on the narrowed head. It is closed by a fact master
holds and by no list: g_uses_finalizers, set where the program's text has
`define_finalizer` at all; such a program seeds no class
(class_exc_ivnil). Guard: test/exception_attribute_finalizer.rb (0 on
master and on the head in 12 cells; nil without the term, checked on a
binary without it). The other blocks CRuby runs later I tried lose no line
(at_exit in both orders, Thread.new with and without join, explicit
stores; in the roads below); `trap` at the top level is astray by master's
AN_EXEC; set_trace_func, TracePoint and refinements are refused by both.
