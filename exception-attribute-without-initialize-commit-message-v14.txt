An attribute of an exception class with no initialize is nil until set, and is marked once set

    class Tagged < StandardError; attr_accessor :tag, :at; end
    kept = []
    60.times do |i|
      s = +"m"
      s << i.to_s
      begin
        raise Tagged, s
      rescue Tagged => e
        e.tag = "tag-#{i}"
        e.at = [i, "a#{i}"]
        kept << e
      end
    end
    # --share-strings: 59 of the 60 read back wrong; CRuby: none

A class of the program's under a builtin exception, with ivars and no
initialize in its chain, has no constructor on its path, so the runtime
builds it. With --share-strings a raise whose message is a String the
program appends to builds the exception at the raise, to hold that
String ("An exception holds a shared String message as its handle"),
and builds it as a plain exception of the base size: the arm typed to
the class wrote its ivars past the end, in a plain run. Before that
change the arm built it itself, at the class's size.

Without the flag the same class was read past its end once an arm that
names no class of the program had caught it. sp_exc_new_for_catch built
it at the base size there too, and a dispatch on the kept value went
past the end of it:

    class ParseError < StandardError; attr_accessor :line, :ctx; end
    kept = []
    begin
      raise ParseError, "m"
    rescue StandardError => e
      kept << e
    end
    kept.each { |v| p v.ctx if v.respond_to?(:ctx) }   # 0; CRuby: nil

A method of the class that stores three ivars segfaulted. An arm typed
to its parent, where the parent is such a class too, built it at the
parent's size, and the ivars the subclass adds were read past that.

A begin with an ensure holds an exception that leaves through its
rescue clauses, raised in a clause or matched by none, as its object
until the ensure has run ("An ensure runs when the exception leaves
through the rescue clauses"), and built it with sp_exc_new_for_catch
too. Raised in a clause and caught afterwards by an arm typed to the
class, 29 of 30 read back wrong, without the flag.

Built by `.new`, or by the rescue that catches a raise by its name, it
had its own size, but sp_exc_new_sub_sized zeroed the struct and gave it
the base exception's scan:

    rows = ->(n) { (0...n).map { |i| [i, "r#{i}"] } }
    e = ParseError.new("m")
    p e.line          # 0; CRuby: nil
    e.ctx = rows.(3)
    20000.times { rows.(3) }
    p e.ctx           # [1, "r1"]; CRuby: the three rows

An ivar nothing had set read as the zero pattern, 0 for a boxed or an
Integer slot, where a constructor seeds nil; and an ivar the program
stored was never marked, and its value was freed under the exception in
a plain run.

One builder cures both. sp_exc_new_sub_ivars takes the class's own scan
and a function that seeds the slots whose nil is not zero
(sp_<Class>__ivnil, emitted beside the scan of such a class, and only
for one the seed is proved for, below). The rescue has to know which
class was raised, and all it holds is the name. The names of these
classes stand in one table of the generated code (sp_xbn_name), and
that code passes a class's row where it raises the class or builds it;
the rescue then knows the class by one range test on the pointer
(sp_exc_own_by_name), whatever the number of classes and the length of
their names, and sp_user_exc_parent is not asked a second time. A raise
that builds the exception itself, and the ensure that holds one, ask
the same entry (sp_exc_catch_own). A name that is no row is built as it
was.

Where sp_exc_new_for_catch built such a class before, a message given
as a frozen literal stays frozen (`e.message.frozen?`,
`e.message << "x"` raising FrozenError): sp_exc_new_sub_caught is the
same builder with that function's own test of the message.

Cost, in instructions under callgrind for one exception built (gcc,
glibc): 20 where master built the class at its own size (`.new`, the
arm that names it), for two more arguments and the nil stores of two
attributes; 45 where an arm typed to a parent of the same kind catches
a subclass raised by name, which is built as itself now; 5 for a
builtin exception caught in a program that has such a class; and an arm
that names no class of the program builds such a class in 133 fewer.
Around these, glibc's strcmp counts 22 to 66 more for the same compares
(17,400,000 calls in 150,000 turns either way): the class's name is a
row of the table and no longer the literal, and strcmp enters by its
page-crossing path by the two addresses' offsets in their pages, for 19
of a turn's 116 compares where master's build has 13. Compiling a
program that only defines such classes runs about 50,000 more
instructions a class: 3.8% more at 300 of them, 1.2% at 2,000.

A program without such a class emits the C it did.
sp_exc_new_for_catch does not change, and sp_exc_new_sub_sized stays,
with the base scan, for a class with an initialize of its own, whose C
does not change either. A builtin exception the program reopens is not
such a class.

"No initialize in its chain" is read from the compiler's class table,
and the table holds what the compiler kept of what it read. Where the
analysis settled a test of the engine and dropped an arm, where a file
was not read, where a module is mixed in or a method is made or named
by something the text does not spell, or where the program gives a
class an `exception` of its own, CRuby may run an initialize or an
accessor the table does not hold, or raise another object than the
class builds. Master's zeroed slot reads 0 there, and 0 may be what
CRuby stored:

    class Counted < StandardError
      attr_accessor :count
      if RUBY_ENGINE == "ruby"
        def initialize(msg = nil)
          super
          @count = 0
        end
      end
    end
    p Counted.new("m").count     # 0, and CRuby: 0

So in such a program these classes are built as they were, and its C
does not change (exc_chain_unknown). The first of the four is a new
global, g_engine_decided, which desugar_engine_branches sets when it
has changed the node table: it has settled a test and dropped what the
test rules out. The other three are one question to master's
an_prog_never_gives, asked of the word `exception`: it answers "may"
for every name where a file was not read (g_require_unread), a module
is mixed in or a name is given by value, so the flag needs no term of
its own; an `exception:` keyword is that word too. The faults above
stand in such a program: 5 of the 20 test programs that hold such a
class, three of them the guards below.

The nil seed asks for more than the size and the scan do. CRuby runs
methods of the program on its own, and the compiler runs few of them:
a parent's `inherited`, the class's own `new`, initialize_copy where an
exception is copied, backtrace and set_backtrace where one is raised,
the class's `===` where an arm matches it, a top-level to_ary where an
Array is flattened. Where one stores a zero, master's zeroed slot is
CRuby's answer:

    class Counted < StandardError
      attr_accessor :count
      def backtrace
        @count = 0
        super
      end
    end
    begin
      raise Counted, "r"
    rescue Counted => e
      p e.count                  # 0, and CRuby: 0
    end

The names CRuby calls are an open list, so the seed goes by what the
text proves and by no name: only to a class from which no method of
the program can be found (class_exc_only_attrs). Its every body, and
every body of each parent the program wrote, up to the builtin
exception, holds attribute declarations with literal names and nothing
else; and in the whole program every def, and every call by one of
an_prog_never_gives's words that gives, takes away, hides or renames a
method or evaluates a block, stands in the body of a class or module,
outside every def and block there, with no receiver but self, so what
it makes is that class's or module's own; and no body or assignment
carries the name of Object, BasicObject, Kernel, Module, Class or a
builtin exception. an_class_only_attrs answers that from a second walk
of the text, beside an_note_written_names, which has proved by then
that nothing is named by value and no module is mixed in. Such a class
answers with its attributes and CRuby's own methods only. Every other
class keeps master's zeroed slots, its attribute 0 until set as on
master, with its own size and scan: the scan reads a zeroed slot as
nothing to mark, as in any object between its allocation and its
constructor, so the two do not wait on the seed. A def at the top
level is Object's, so a program with one seeds no class. Nor does a
program with a finalizer (master's g_uses_finalizers): the collector
runs that block when it chooses, and CRuby's chooses another moment,
so a slot the block is to store 0 in reads 0 on master before it has
run. Of the 15 test programs that hold such a class and are built
this way, 7 hold a class that takes the seed.

Not here: a class read off a value (`raise x.class, "re"`). Its name
reaches the raise as a copy (sp_exc_class_name), which is no row: no
initialize runs for it, and a class without one is still built at the
base size. And a subclass caught by an arm typed to a parent that has a
method of its own and no attribute, or by a bare arm typed to the
parent, is still built at the parent's size, as before: its attribute
does not read nil there, and ivars a method of the subclass stores go
past the object.
