A constant holding a class names it in is_a?, kind_of? and instance_of?

    K = Integer
    p 7.is_a?(K)

printed false; CRuby prints true. kind_of? and instance_of? did the
same, for a builtin class or module, a class of the program's own, a
Struct and an exception class behind the constant, on a typed and on a
boxed receiver, so `raise TypeError unless v.is_a?(K)` raised. The
emitters read the argument's name (isa_const_name, isa_match_name), and
K names no class. `K === 7` and `K.new` were right:
rewrite_const_alias_receivers rewrites a receiver's name to the class
resolve_class_alias finds.

It now rewrites the argument of the three too, so every arm and the
narrowing after the test see the class, and the C is that of the call
written with the class.

Only where the constant holds that class when the call runs: the
program writes it once, as a statement `K = C` or `K = Mod::C` with
Mod its own. A read at the program's or a class body's own level sits
in a later statement. A read in a method body needs a write that no
method of the program can run before: only defs, classes, constants
and declarations precede it. A second write holds what was written
last, `IO::Buffer` is not the program's Buffer, and before the write
CRuby raises NameError. A file required inside a def, a block or an
expression is spliced ahead of that statement and loads when the
require runs: the parser marks the constant writes of such a file
(`req_late`), and they are left alone.

And only where the read names that constant: `::K` reads the program's
own level, `Mod::K` the body of a top-level Mod, a bare `K` the
program's level or a body the read sits in. `class K` under a module
reopens the class another body's constant `K` holds (walk_scope), so
the class behind the constant must be opened by its own definition
alone. Inside a class or module CRuby looks a bare name up in that
body and in what the class inherits or mixes in before the program's
level: where the program opens, inherits or mixes in one of CRuby's
namespaces that hold constants (`module Process`, `include Math`,
`< File`), a bare read in another body than the write's is left. A
write's value is read where the write stands, by the same lookup
(`ERR = DomainError` under `include Math` holds Math's, and so does
`K = Calc::DomainError`): there, a bare value is taken at the
program's own level alone, and a path's where the class is defined in
the body the path names.

A constant named by const_set, private_constant or remove_const is
left alone, and so is a program that defines is_a?, kind_of? or
instance_of? itself, or a class under BasicObject: there the builtin
test is not what answers.

Not here: `K ||= C`, `Mod::K = C`, a multiple assignment,
`K = 5.class`, a write under a condition, a constant of a constant
(`J = K`), a class opened twice, and a method's read in a program that
prints or calls before the constant's write. They answer as before.

Tests: test/const_alias_is_a.rb, and one program each for the four
that leave a whole program alone, a body's reads or a file's writes:
test/const_alias_is_a_own.rb, test/const_alias_is_a_basic.rb,
test/const_alias_is_a_scope.rb, test/const_alias_is_a_late.rb.
