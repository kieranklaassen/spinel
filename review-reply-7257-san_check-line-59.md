Fixed in 93172906 and a1acf45d. The per-program files are named by the program's place in the list, not by its path, so two paths can no longer share a log and one program named twice is counted twice. The number travels with the path as one NUL-ended item (`xargs -0 -n 1`), which GNU and BSD xargs both pass through untouched; my first form joined them with a tab under -I, which BSD xargs turns into a space, and a1acf45d corrects that. The script also counts the programs whose compile was tried against the list and ends with status 2 when they differ, so a dispatch that runs nothing cannot read as clean. No pair in the corpus collided (0 of 5,682), so `make san-check` was not affected; with paths named on the command line a report could be lost, which I reproduced before the change ("2 programs, 0 with a report" for t/a_b.rb and t/a/b.rb with one job).
