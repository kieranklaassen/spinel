Every `...` forward beside a yielding `super(...)` is given the block

    class Reader
      def each_row(n) = yield(n)
    end
    class Logged < Reader
      def each_row(...) = [super(...), note(...)]
      def note(n) = block_given? ? yield(n) : -1
    end
    p Logged.new.each_row(2) { |x| x * 3 }    # [6, 6]

answered [6, -1], and with a bare `yield` in `note` it raised "no block
given (yield)".

A method whose `super(...)` reaches a parent that yields keeps its `...`
and is inlined at the call, so that the site's block is spliced at the
parent's yield. emit_inline_call_x chooses the block an inlined callee's
yields run from the call's own block node, and takes the block the site
runs under only for `inner(&)` and `inner(&b)`. `note(...)` has no block
node, so it was inlined as a call with no block, beside a `super(...)`
that was given it.

The forward takes that block as `inner(&)` does, where the splice is
known to build: not a block that can `break`; where the callee reads
the value of a yield, only a block whose last statement has a C value
there; and not into a callee with a default the forward would fill by
position. Elsewhere the forward is left as it was, so a program whose
block leaves before the forward is reached still builds and runs. The
method's proc form forwards its proc only where every literal block the
program hands a method of that name is taken: it serves every site, and
a program that did not build is not built into a site's LocalJumpError.
