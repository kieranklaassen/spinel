A String handle local reads as nil after a builtin answers nil

    def greeting
      who = ENV["NO_SUCH_VARIABLE"]
      return "nobody" if who.nil?
      who << ", "
      who << "hello"
      who
    end
    puts greeting

died with SIGSEGV; CRuby prints nobody. The two appends make who an
sp_String handle, ENV's miss leaves it NULL, and its read tests the
handle only where the nil fact says the local may be nil. nf_call
(analyze_nil.c) took every String a builtin call answers as not nil,
except a container's picks and a String's slice. It now answers
may-be-nil for a String's bang method that changed nothing (the
table's BOPF_SELF_OR_NIL), for ENV's [], fetch and delete, a
MatchData's [] and Regexp.last_match(n), gets, and an IO's getc and
read(n); bsearch joins the picks. None is a nil the program writes, so
no call gains a guard: only the handle's read changes.
