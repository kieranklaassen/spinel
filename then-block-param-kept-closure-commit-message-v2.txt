A block kept from inside a then or tap block reads its own run's parameter

    def keep(&b) = b
    fs = [7, 8, 9].map { |e| x = e; x.then { |v| keep { v + 1 } } }
    p fs.map(&:call)

printed [9, 10, 10] where CRuby prints [8, 9, 10]: each block that a
method kept read the parameter of the run after its own, and the last
one its own. A yield_self block did the same, and a tap block whose
value is used. A proc or a lambda made there has a capture of its own
and was right already.

A then or tap block is spliced into the frame, and a parameter that a
kept block captures lives in a cell. The body's prologue makes that
cell anew at each run and stores the parameter in it
(emit_block_locals_reset), so a block keeps the cell of its run. The
binding stored the parameter into the cell too, ahead of the prologue,
where the cell is still the one the previous run's block holds.

The binding now fills the plain slot only. Both ways the body is
emitted (emit_block_value_into for then, emit_iter_step_body for tap)
run the prologue before the first statement, so nothing read the cell
between the two stores. emit_cell_shadow_store has no caller left and
is removed.
