A String Range in a global, a constant or a class variable keeps its ends

    def span(i)
      a = "a#{i}"
      z = "z#{i}"
      (a..z)
    end
    def junk(i)
      (1..200).map { |k| "j#{k}" }.size
    end
    $r = ("a".."z")
    bad = 0
    i = 0
    while i < 2000
      $r = span(i)
      junk(i)
      bad += 1 unless $r.first == "a#{i}"
      i += 1
    end
    puts "global: #{bad}"

printed `global: 22` in a plain run, with gcc and with clang; CRuby
prints `global: 0`. A class variable and a class-level instance variable
were wrong in the same 22 turns of 2,000, and a constant written once
read wrong in 1,972. With SPINEL_GC_STRESS=1 the global was wrong in
1,967 turns, and level 2 stopped at "the mark reached a freed heap
string".

A String Range sits in its file-scope slot by value and carries two GC
strings. The lines codegen_program writes into sp_mark_user_globals mark
a slot that is a String, a boxed value or a reference, and ask needs_root
for the last, which says no for a slot that is not itself a reference.
Nothing marked the two ends, and the next collection freed them while the
slot still named them.

The four loops that write those lines (globals, constants, class-level
instance variables, class variables) now share one function,
emit_static_slot_mark, which marks each end of a String Range as
emit_class_scan does for an instance variable (upstream 4353). A class
or a Struct with a String Range instance variable or member has a
class-level slot of that name, so its program gains the two mark lines
for it as well. Every other program gets the C it had.

Not here: an instance variable or a Struct member holding a String Range
takes no write barrier (its own commit); a constant whose two ends are
both made in the assignment loses the first before the slot is written;
and inspect of a String Range does not hold the text of its first end
while it makes the second.

Test: test/str_range_static_slot.rb (expected from CRuby 3.3.6), in
GC_STRESS_TESTS, where without the change the run aborts; its section
of 2,000 turns counts wrong turns in a plain run too. The C of two
corpus programs changes (range_dup_unfrozen, str_range_endpoints_root),
by the mark lines of their String Range slots; optcarrot has none.
