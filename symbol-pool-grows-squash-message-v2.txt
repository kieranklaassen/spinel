A program that makes more than 8,192 Symbols at run time keeps them apart

The pool of Symbols made at run time was a fixed array of
SP_DYN_SYMS_MAX entries, 8,192. Once it was full sp_sym_intern_n
answered (sp_sym)0 for every new name, the first Symbol of the
program's table, and nothing raised:

    h = {}
    20_000.times { |i| h[("k" + i.to_s).to_sym] = i }
    p h.size                    # 20000 in Ruby; 8193

to_sym, intern, :"k#{i}", map(&:to_sym), transform_keys(&:to_sym) and
JSON.parse(text, symbolize_names: true) all make their Symbols there.

The static array stays the pool's first block, so -DSP_DYN_SYMS_MAX=<n>
still sizes what a program that interns little pays for. A full pool
moves to a heap block twice the size (sp_dyn_syms_grow, cold and out of
line), and the marker and the lookups walk a pointer to the block in
use. A program that stays under the limit is given the same ids in the
same order, and a lookup costs what it did.

The block a full pool leaves is kept. A Thread reads a Symbol's name
through the pool's address with no lock, and a loop keeps that address
across its turns; every id a reader can hold was made before the move,
so its entry in the old block is true. The heap blocks left behind sum
to 131,072 bytes less than the one in use.

The lookup is the linear walk it was.

test/symbol_pool_grows.rb makes 10,000 Symbols three ways.
test/symbol_pool_grows_thread.rb has two Threads read two Symbols'
names while the main Thread makes 17,000 more.
