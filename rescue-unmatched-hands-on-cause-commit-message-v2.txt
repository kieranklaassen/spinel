A rescue that does not match hands the exception on with its cause

    def go
      begin
        raise ArgumentError, "first"
      rescue ArgumentError
        raise TypeError, "second"
      end
    end

    begin
      begin
        go
      rescue IOError
        puts "io"
      end
    rescue => g
      p g.cause
    end

printed nil, and inside another handler it printed that handler's
exception. CRuby prints #<ArgumentError: first>.

The cause is decided at every raise, from what is being handled there,
and a rescue none of whose clauses match hands the exception on by
raising it again: where it passes, nothing is being handled, or
something else is. The arm for no match, and the rescue modifier's arm
for an exception that is no StandardError, now call `sp_exc_pass_cause`,
which gives that raise the cause the exception was raised with. An
object that carries a cause of its own keeps it.

One cause is not handed on: an exception an ensure body had in flight.
A return or a break out of that body drops the exception, but
sp_inflight_cause still names it, and the next raise takes it as its
cause. That raise is left as it was (sp_pending_cause_own), so such a
program answers what it answered.

Left alone: an ensure on the way still loses the cause.
