setbyte reads a handle's buffer after its arguments have run

    s = +"abc"
    t = s
    s.setbyte(0, (s << ("x" * 4000); 0x41))
    p s[0]

printed "a" in a plain run; CRuby prints "A". valgrind reported an
invalid read in sp_str_setbyte_cow, inside a block realloc had freed.
The index form, s.setbyte((s << ("x" * 4000); 0), 0x41), did the same.

For a String held by a handle (one under two names, or reached through
a reader) emit_scalar_call_arms read the handle's buffer pointer and
then ran the value and the index. An append inside either one grows
the handle and frees the buffer it had, so the byte went into the freed
block and the String kept its old byte.

The arguments now run ahead of that read, as the shims run theirs
(sb_shim_args_first), and the frozen check and the buffer's read
follow them. This is CRuby's order as well: the index runs before the
value, and an argument that freezes the String makes the write raise.
Two arguments that are pure reads (subtree_is_pure_read) run no code
and allocate nothing, and the arm keeps the C it had for them.

The handle is read before the arguments and used after them, so it has
to live through them. A local holds its handle unless an argument
rebinds the local (read_rebound_by). A handle a reader answered is
held only by its object, which nothing may hold:

    def fresh = Box.new(+"abcdef")
    p fresh.b.setbyte(0, (keep << churn.last; 0x41))

printed 65 on master and wrote the byte into a buffer the collector
had freed (valgrind at SPINEL_GC_STRESS=2: six errors in
sp_str_setbyte_cow). Such a handle is now rooted while the arguments
run, unless both are pure reads.

Cost (callgrind, instructions a call): the root is 15, where the
String comes through a reader and an argument is a method call
(o.b.setbyte(i & 63, byte(i)): 92 to 107). Every other call measured
costs what it did: s.setbyte(i & 63, 65) under two names 80 to 80 and
through a reader 77 to 77; s.setbyte(i & 63, byte(i)) on a local
82 to 82; o.b.setbyte(i & 63, v[i & 1]) 91 to 91.

Not here: setbyte on an Array element or a Hash value whose argument
appends to it still ends in a segfault.
