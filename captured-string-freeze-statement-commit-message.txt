freeze as a statement reaches a String a proc captures

    s = "qr".dup
    t = s
    t.freeze
    l = -> { t << "x" }
    l.call                  # FrozenError

did not build: 'lv_t' undeclared. The statement arm of freeze froze a
shared String local through `lv_<name>`. A local a proc captures is in
its cell, so that C local is not there, outside the proc (above) or
inside it (`l = -> { t.freeze; 1 }`).

The arm now takes the handle through emit_local_ref, which reads the
cell or the capture. freeze in value position already went through
strbuf_slot_ref and is unchanged, and so is the C of a local no proc
captures.

Of 63 programs that freeze a captured String on one side of a proc
and change it on the other, 19 were right and 44 did not build; the
63 are right now.

Test: test/captured_string_freeze.rb (expected from CRuby 3.3.6). No
other program of the corpus changes its generated C.
