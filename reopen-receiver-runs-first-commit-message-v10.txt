A method added to a builtin runs its receiver before its arguments

    class String
      def pair(a) = "#{size} #{a.size}"
    end
    puts recv.pair(arg)

ran arg before recv, with gcc and with clang, for a method the program
adds to Object, Kernel, String, Symbol, Float, Range, Array, Hash or
Numeric, and to Integer where the method has a rest or a keyword; a
class's own method runs recv first, as CRuby does. Those arms wrote the
receiver in place, one C argument beside the others, while
emit_args_filled runs an argument that allocates ahead of the
statement. An argument that only reads was read too early the same
way: `setg.pair($g)` passed the $g that setg had not yet assigned. And
a rest or a default made in place stood beside that receiver with no
root, so for `Door.new.note(m)` against `def note(m, *r)` gcc made the
Array first and Door.new collected it (r.size answered 3 in a plain
run), and clang made the Door first and the Array's allocation could
collect that.

emit_reopen_recv_in_order opens such a call as a statement expression,
in place: the receiver bound to a rooted temp, then what the arguments
hoist, then the call. It does so when the receiver has an effect and an
argument (or a default the call leaves out) has one too, when the
receiver can change what such an argument reads (read_rebound_by), or
when the receiver allocates and the method has a rest or leaves out a
default that allocates. The box of an Array, a Hash or an object is
held as its pointer and boxed where the call takes it: a pointer's
root is a push and a pop. A String, or an object passed by value, that
Object's method takes is held boxed, in a slot of the frame.

A String held ahead of the arguments is the String as it was, and the
call read it after them: `cur.pair(add)`, where cur answers $s and add
appends to $s, passed the longer one, as CRuby's one object shows it.
So beside an argument, or such a default, that can run the program's
code (anything but reads, literals and what is made of them; a name
the program gave the builtin, `[]` on an Array, an operator on an
operand that is no Integer or Float, `5 == o`, and the hash of a key
that is no String, Symbol or Integer are such code: arg_runs_nothing)
the receiver is held only where the held value is what the call would
read after it (recv_held_as_read): a scalar, a Range, the pointer of
an Array, a Hash or an object, an interpolation CRuby makes a new
String for (one with a plain part that is not empty, or of one
embedded part: `"#{s}#{""}"` answers s itself), or a String from a
call proved to make its own (recv_new_string). The proof is by what
the program does not hold: the call is one of 30 String builtins that
always answer a new String and that str_fresh_value takes for one too
(not clamp, which answers its receiver), an Integer's or a Float's
to_s or inspect, or it reaches the one def of that name, whose body
ends in such a String and has no return; and the program as written
holds no other def of that name, no Symbol of that name, and no site
where a method is named, made or loaded by something the text does
not spell (an_prog_never_gives): a call that takes a method's name
(send, method, to_proc, inject with an operand no literal block
follows, define_method, alias_method, an attr or a visibility word)
with a name that is no Symbol literal, or one that calls, reads or
renames another such word by its Symbol; a block-pass of anything but
a Symbol literal that is no such word, a literal `->` lambda, or the
block parameter of its own def (`&proc { }` and `&lambda { }` are
sites: a program can give either name a method); text evaluated (eval,
instance_exec, binding, ERB); a file the compiler did not read
(g_require_unread); a module mixed in (an include, a prepend or an
extend with an argument that is no literal, a hook beneath them called
by hand, or one of those six words as a def or as a Symbol). A module
mixed in runs its methods ahead of a class's own, of its parent's or
of an object's class's, and a core module's are no text of the
program's: after `class String; prepend Kernel; end` Kernel's itself
runs for the program's one def of it. That a constant names a module
of the program's own is not proved here, so a program that mixes in
its own keeps master's C as well. analyze_program reads this ahead of
every rewrite, since a desugar erases such a call.

The parser's rewrites erase a require the same way, so it leaves
g_require_unread clear only by the text of each file it reads, as
written, every character of it: no load-path global is written
($LOAD_PATH, $:, $-I, $LOADED_FEATURES, $"), nothing named load or
autoload is, and every require and require_relative written was
resolved, which one with a computed name, one it warns it ignores and
one in a branch it rules dead are not. What its class macros write is
read again for those globals, load and autoload; a require a macro
writes stays a call, which the walk finds. The words are counted, not
parsed: one in a string or in a comment keeps master's C. Any other
call is emitted as it was.
