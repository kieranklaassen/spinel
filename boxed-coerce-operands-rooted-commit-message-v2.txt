Boxed coerce keeps an operand made in place while the pair is made

    r = [3r / 4, :a][0]
    pr = r.coerce(Rational(i, 1))

run a million times, keeping every fourth pair, left the pair for
i = 2172 holding [(2178/1), (3/4)]. sp_poly_coerce allocates the Array
it answers with before it stores its operands, and a Rational or a
Bignum handed over boxed is a cell: one made in the argument list is
held by nothing while that Array is made. Under SPINEL_GC_STRESS=1 the
pairs come out wrong, and under 2 the mark stops on the freed cell.

The pair keeps the operands themselves, so the call holds them: the
two arms that write sp_poly_coerce for a boxed receiver or operand bind
a value made in place to a rooted temporary, as the Bignum receiver's
arm does. A typed Rational is a struct in C and is copied into a new
cell where it is boxed, so its box is made in place also when the
value is read from a variable: q = Rational(i, 1); r.coerce(q) left
the same wrong pair. A read of a boxed variable, an Integer and a
Float keep their C, and so does an element read out of a variable's
Array of boxed values (a[0].coerce(2.5)): the Array holds it while no
other code runs. A receiver that is another call's answer
(o.v.coerce(2.5)) pays one frame slot.
