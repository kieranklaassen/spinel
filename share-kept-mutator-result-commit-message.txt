Under --share-strings a kept mutator result is its receiver's String

`@r = @s.concat("x", "y")` followed by a long `@s << ...` printed 4 for
`@r.size` under --share-strings where CRuby prints 85. A call that
changes its receiver in place answers the receiver, and the rule already
puts the slot that keeps that answer in the receiver's class and makes
it the shared handle. The write then filled the slot with a new String
made from the call's bytes: the two names were two Strings, and a later
change through one did not reach the other.

The write now hands over the receiver's handle. Where the value is
`concat`, `<<`, `prepend`, `replace` or `clear` on a variable that holds
the handle (through `<<` and `concat` links), and the rule's facts have
the call's value and that variable in one class, the call is emitted
under the handle mark, where its emitter already answers the receiver
itself. A local's, an instance variable's and a global's write take it.

The sharing pass is not changed: it gains no route and no name. Without
the flag the generated C is master's.

The refusal of an instance variable assigned from another refused
`@t = @s.replace(x)`, `@t = @s.prepend(x)` and `@t = @s.clear` under the
flag because that write copied. It no longer does, so those three are
left to the rule there, as a bang's kept result is.
