A String handle local that may be nil reads as nil

    t = +""
    t << "a"
    t << "b"
    t = nil
    p t

died with SIGSEGV; CRuby prints nil. Two appends in a row, or one in a
loop, make t an sp_String handle (TY_STRBUF), and nil is a NULL handle.
The local read in emit_local_ivar_write_expr copies sp_String_cstr(t),
and tested the handle only for a parameter, a dynamic handle and a
shared one. It now tests it wherever the nil fact says the local may be
nil (Repr.may_nil); a local the fact proves not nil keeps its C.

The same handle read before its first write (assigned only in a branch
not taken) had no fact: the definite-assignment seed in an_nil_facts
skipped a TY_STRBUF local, so `t.size` there had no nil target and died
too. The seed now covers it, and the call raises NoMethodError as it
does for a handle assigned nil.

The read stays untested where its nil would be past a NoMethodError
the call plan does not raise (nil_fact_unraised): the plan guards no
call for a nil it cannot bound, such as a slice that missed. There an
append does nothing on the NULL handle, and a nil read after it, or as
the receiver of a call nil does not answer, would hide CRuby's error.
