A FACT ABOUT THE TIP, not this piece's and not cured here (it is another pull request's ground, "An attribute of an exception class with no initialize is kept once set"): on bare c52df8a11741 this program dies of signal 11 at -O0 and -O2, in a plain run and under both stress modes; CRuby prints -13, wide, ArgumentError, kept 0, ArgumentError, kept 1.

      class Wide < StandardError
        attr_accessor :a, :b, :c, :d, :e, :f, :g, :h, :i, :j, :k, :l
      end

      def go
        raise Wide, "wide"
      ensure
        $kept = [ArgumentError.new("kept 0"), ArgumentError.new("kept 1")]
      end

      begin
        go
      rescue Wide => x
        x.a = -1; x.b = -2; x.c = -3; x.d = -4; x.e = -5; x.f = -6
        x.g = -7; x.h = -8; x.i = -9; x.j = -10; x.k = -11; x.l = -12
        puts x.a + x.l
        puts x.message
      end
      $kept.each { |o| puts o.class, o.message }

   The ensure's entry statement makes the exception's object by name, of the base size, and keeps it as the exception's; the raise after the body carries it; and a rescue clause that binds a class of the program with ivars takes a carried object as that class's own struct (emit_rescue: `sp_exc_obj[sp_exc_top] ? (sp_Exception *)sp_exc_obj[sp_exc_top] : sp_exc_new_sub_sized(...)`), so the clause's twelve stores run past it. With four attributes the same program prints CRuby's lines. With `raise Wide.new("wide")`, or with an `initialize` in the class, it is right: the object is then made at the raise, of the class's size. With the raise inside a rescue (`begin raise KeyError, "first" rescue KeyError; raise Wide, "wide" end`), so that a cause waits and the object is made at the catch, it dies the same way, and did before this tip. Neither test of this pull request has a class with ivars and no `initialize`.
