=====
scan with a String pattern finds it by bytes

`"a\0b".scan("b")` answered [] and `"x,a\0b".scan("a\0b")[0].bytesize`
was 1: sp_str_scan measured the pattern by strlen and searched with
strstr, which ends at the subject's first NUL byte. sp_str_scan_at,
the turn of a block that reads `$~`, did the same.

Both read byte lengths and search with sp_str_find. One byte is found
by memchr. A longer pattern is still sought by strstr. Where strstr
finds nothing, one strlen says where it ended: at the String's end
there is nothing more to find, and behind a NUL inside the String
sp_str_find_rest looks by sp_bytestr. A pattern without a NUL cannot
lie across that NUL, so nothing is missed. strstr reads the pattern to
its first NUL too, so at a call's first hit the strlen of the pattern
that each function took at its top says whether the pattern holds one;
if it does, that search and the later ones go by sp_bytestr. The
pattern is walked no more often than before, and not at all by a call
that finds nothing. The strlen and its compare are inline, so a
subject without a NUL is searched as before and pays one strlen of
what is left of it when a pattern of two bytes or more is not found,
or once behind its last occurrence. The empty pattern walks to the
byte length too.

=====
lines with a separator reads the String by bytes

`"a\0b".lines("\0")` answered ["a"], and `"\0ab".lines("b")` answered
[]: sp_str_lines_sep took a String that begins with a NUL byte for the
empty one, measured the String and the separator by strlen and
searched with strstr, so the lines ended at the String's first NUL
byte. The chomp: form measured each line by strlen again.

Both read byte lengths, and the separator is found by sp_str_find.
each_line with a separator rides them.
