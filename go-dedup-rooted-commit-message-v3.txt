sp_str_dedup copies its String before a collection can free it

    a = "x" * 100_000
    b = "y" * 100_000
    x = -(a + b)
    p x[0, 3], x.count("x")

printed "\u0000\u0000\u0000" and 3984; CRuby prints "xxx" and 100000.
When the content is not interned yet sp_str_dedup allocates the frozen
copy with sp_str_from_bytes, and nothing held the String it copies
from: a collection in that allocation freed a receiver the caller had
just built, and the copy was made of freed bytes. A String this large
starts that collection in a plain run; a short one does under
SPINEL_GC_STRESS=2, as does `(a + b).dedup`.

The copy is now allocated with sp_str_alloc_nogc, which runs no
collection first: the allocator sp_msg_heapify uses for a String it
cannot root. The next ordinary allocation collects.

Test: test/string_dedup_fresh_held.rb, which joins GC_STRESS_TESTS.
