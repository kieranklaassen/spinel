## What this changes

A splatted Range among the indexes of `values_at` on a boxed receiver gave none of its members, and a splatted Integer was dropped:

```ruby
a = [[10, 20, 30], nil][ARGV.size]
p a.values_at(*(0..1))      # []; CRuby: [10, 20]
p a.values_at(0, *(1..2))   # [10]; CRuby: [10, 20, 30]
p a.values_at(*2)           # []; CRuby: [30]
```

No loop costs more. By callgrind `a.values_at(0, *r)` with `r = (2..1)` ran 696 instructions a call and runs 445 (gcc; clang 690 and 440). A splatted scalar that is nil when the call runs is the one read that was right and now passes a new test, the one for nil: it ran 615 and runs 448 (605 and 443). A splatted Array, boxed or not, and a splatted `nil` run what they ran. Nor does the compiler do more: one call with 2,000 splats took 361,195,868 instructions to compile and takes 283,921,965.

`values_at` on a boxed receiver reads a splatted list with `sp_poly_to_poly_array`, which copies an Array and so answers none for what is no Array; the call then answered from its other indexes alone. An operand typed as an Integer Range now has its members walked onto the list of indexes where it has both its ends (`sp_poly_values_at_range`, with no array between). One typed as a scalar is pushed as the index it is unless it is nil when the call runs (`sp_poly_values_at_scalar`): what is typed Integer, Float or String can hold nil (a local set on one branch, a parameter left out, a method's value, an element), and nil splats to none, as it did.

A splat asks its operand `to_a`, and a Range's `to_a` walks its `each`; both arms answer for the built-in ones. So neither arm is taken, and the splat is read as before, in a program that may have given a class its own: one with a def, a Symbol or a String named `to_a` (`each` too, for the Range arm), `method_missing`, `respond_to_missing?` or `respond_to?`, for an alias gives a method as a def does (a block argument written `&:to_a` names none and switches nothing off); with the Symbol or the String `define_method`, `define_singleton_method` or `alias_method`, or a call of one of those three whose name is not written out; with a `class_eval`, a `module_eval` or an `instance_eval` given a text, or one of them or `eval` named by a Symbol or a String; and one whose text CRuby may run more of than the compiler read: a program that may load a file the compiler did not read (`g_require_unread`), or in which the analysis decided a test for this engine and dropped an arm (`if RUBY_ENGINE == "ruby"`). For the second, `desugar_engine_branches` now says so in `g_engine_decided`, set where it has changed the node table: eight lines in `src/analyze_desugar.c` and `src/compiler.h`, which the pull request "A boxed Integer's [] reads a Rational, nil or Bignum index" adds as well, the same bytes, so whichever of the two merges second merges them clean. Each name is also asked of the walk of the program as written (`an_prog_never_gives`), which read the text ahead of every desugar and knows a name sent by value, a block passed by value, a text evaluated and a `binding`. 75 such programs print master's lines: with a `to_a` on Integer, Float, String, Symbol, Range, NilClass, Numeric, Comparable, Kernel, Object, a class of the program's or at the top level; with a `to_a`, a `Range#each` or a `method_missing` given by a def, `alias`, `alias_method` or `define_method` (the name a Symbol, a String or computed), `send`, a prepended module, Enumerable or Comparable; with a `respond_to?`, an `each` of another class or the Symbol `:to_a` alone; with a text handed to `class_eval`, `module_eval` or `instance_eval`, directly or through `send`, `public_send`, `__send__` or a Symbol's proc; with a `load`, an `autoload` or a `require` the compiler cannot resolve; and with an arm under a test decided for this engine.

A scalar pushed as an index can be one `values_at` refuses, a NaN or a String, and then the runtime raises as it does for that index written without the splat. A `raise` written in a program runs an `initialize` that a reopened builtin exception class gives (`class RangeError; def initialize(m = nil) = super("[]"); end`), and the runtime's raise does not, so in a program that reopens such a class neither arm is taken (`any_exc_reopen`). A program that changes what such a class does when it is raised or rescued by a road master's own `raise` does not take either (`class RangeError < StandardError`; a `===` given to `Module`) sees here what a `raise RangeError` written at that place prints on master.

Nor is an arm taken where the operand is not read when CRuby reads it. Master holds an argument that has an effect in a temp ahead of the statement and reads the splat's operand after it, so in `a.values_at(*j, (j = 1; 0))` the operand read is the one that argument left, not the one CRuby splats. And it builds the list of indexes before it evaluates the receiver, so in `(j = nil; a).values_at(*j)` the operand is read before the receiver assigns it. Such a splat is read as before: one with a later argument held so, unless its operand is held in its place too, and one whose receiver is more than a read of a variable and is not held.

Every other operand is read as before, in the same C: an Array, nil, and anything boxed. Of 768 programs (four receivers, 48 operands, four places in the list), 160 compile to the same C. Of the other 608, 304 answered wrongly and now print CRuby's line. 176 were right and are: they splat an empty Range or a scalar that is nil when the call runs, and nothing is what those hold. The last 128 print the same wrong line on both and are listed below. None that was right is lost, in the default mode, with `--int-overflow=promote` or with `--share-strings`; nor in 48 programs of 58 reads whose later argument or receiver assigns the operand, or whose operand or receiver is a local that a Fiber, an Enumerator or a Thread shares with a scope that assigns it meanwhile.

Not here, each still as on master:

- a splatted boxed Range or boxed Integer, `k = [1, nil][0]; a.values_at(*k)`, prints `[]` (CRuby: `[20]`): 32 of the 768. Under `--int-overflow=promote` an Integer local or a method's Integer is such a box.
- a Range without an end gives none where CRuby raises, RangeError for `*(1..)` and TypeError for `*(..1)`; so does one whose end is nil when the call runs: 64. The largest Integer as a Range's end and the smallest as its begin read as no end, so `*((x - 1)..x)` with the largest `x` gives none (CRuby: two nils): 48.
- the smallest Integer as a splatted scalar reads as nil and gives none (CRuby: one nil): 16.
- a splatted String Range or Float Range adds nothing where CRuby raises TypeError: 32.
- a splatted empty Array literal as the only index, `a.values_at(*[])`, raises NoMethodError (CRuby: `[]`).
- a program with a def, a Symbol or a String named `to_a`, or any other of the names above, keeps every answer it had, a splatted Range's none among them; a `respond_to?(:to_a)` is enough, and so is a site that names a method by value. So does one that may load a file the compiler did not read (the words are counted in its text, so a `load` in a String or in a comment is enough) and one in which a test is decided for this engine, also where the arm kept is the one CRuby takes. And so does one that reopens a builtin exception class (`class RangeError`), for whatever method.
- a splat whose later argument has an effect, or whose receiver is more than a read of a variable (a call, a sequence, an element whose index has an effect), is read as on master: `a.values_at(*r, (r = (0..1); 2))` with `r = (2..1)` prints `[30]`, CRuby's line, and `geta(a).values_at(*(0..1))` still prints `[]`.
- a call with two splats can be cured in one and not in the other. In `i = 0; a.values_at((i += 1; 0), *i, (i += 1; 0), *i)` the first splat is still dropped and the last is now read: `[10, 10, 30]`, where master prints `[10, 10]` (CRuby: `[10, 20, 10, 30]`); and a boxed operand beside a typed one, `a.values_at(*k, *(0..1))`, gives the typed one's members alone.
