## What this changes

A boxed Integer read by a boxed index that is a Rational, a Complex, a Bignum, `nil`, `true` or `false` answers bit 0:

```ruby
a = [5, Rational(3, 2), nil, "s"]
x = a[0]
p x[a[1]]   # 1; CRuby: 0
k = a[2]
p x[k]      # 1; CRuby: no implicit conversion of nil into Integer (TypeError)
```

`sp_poly_index_poly` reads one bit of a boxed Integer by an Integer or a Float index, and a bit field by an Integer Range. An index of any other kind that no earlier arm takes falls to its last line, which reads offset 0. `sp_poly_index_poly_conv` is that function, line for line, with one block ahead of the last line: a Rational or a Complex with no imaginary part is the Integer it converts to, and `nil`, `true` or `false` is CRuby's TypeError. An index past a word (a Bignum, or a Rational or a Complex that large) reads the receiver's sign above its bits and 0 below; a Bignum receiver takes a Bignum so, and for any other index that large raises CRuby's RangeError. Those kinds are listed, and every other still reads bit 0.

`sp_poly_index_poly` is as it was, and so is every caller of it but one: a read written `x[k]` takes the new function where it is proved to answer the same whichever of its receiver and its index runs first. The index can run first: a block the compiler runs in line (`$x[k.tap { $x = v }]`) and a `case` (`o.v[case n when 1 then o.v = w; k end]`) are both ahead of the receiver. The bit is then read of the value the index assigned, and bit 0 of that can be CRuby's bit of the value before. Two shapes are proved:

- a receiver that is a local in its own C variable, whose index names that local nowhere but to read it. Nothing else writes such a local;
- a receiver and an index that each run none of the program's code. Listed for that are number, Symbol and String literals, reads of variables and of the program's constants (but one set by `K = SomeClass.new`), a typed Array read by a typed Integer in a program with no `[]` of its own, and an operator of an Integer or a Float with a number or a boolean in a program with no operator of its own. Under a receiver that is a bare global, instance variable or class variable, or a local a proc shares, the index may also plainly write a local, an instance variable or a class variable of another name. A write of a global is not listed, for another name can reach it (`alias $y $x`; `$-d` is `$DEBUG`); nor is any other call.

Whatever the receiver, four things leave a read to `sp_poly_index_poly`:

- an index that holds `nil`, `true` or `false`: a `require` in a statement is replaced by one of the three while its file runs ahead of the statement, and the file's top level can write a local of the requiring top level too. The read a `method(:[])` object makes, whose index is its own parameter, is left as well;
- a program whose text CRuby may run more of than the compiler read: one that may load a file the compiler did not read (`g_require_unread`), or one in which the analysis decided a test for this engine and dropped an arm (`if RUBY_ENGINE == "ruby"`). What CRuby runs there can give Integer a `[]` or an operator of its own, and bit 0 can be what CRuby's call of it answers. For the second, `desugar_engine_branches` now says so in `g_engine_decided`, set where it has changed the node table: eight lines in `src/analyze_desugar.c` and `src/compiler.h`, which the pull request "A splatted Range in a boxed values_at answers its elements" adds as well, the same bytes, so whichever of the two merges second merges them clean;
- a program that may itself have given a class a method the read calls: `[]`; `begin`, by which `Integer#[]` asks an index that is no Integer whether it is a Range (`rb_range_values`); `to_int`, which it asks next (`rb_to_integer`), and `to_i`, by which a Numeric answers it; and `respond_to?`, `respond_to_missing?` and `method_missing`, which each of those asks goes through (`rb_check_funcall`). A `to_int` the program gives Rational answers `x[3/2r]`, and bit 0 can be the bit it names; a `respond_to?` that answers false makes the read a TypeError, and a rescue can print what bit 0 printed. That is asked of the walk of the program as written (`an_prog_never_gives`): no def and no Symbol of the name, and nowhere a name sent by value, a text evaluated or a `binding`, which give a method that no node shows;
- a program that reopens a builtin exception class (`any_exc_reopen`): CRuby runs an `initialize` such a class gives for the TypeError of `x[true]` too, and a rescue can print what bit 0 printed. A `raise` the program writes runs it; a raise by the runtime does not.

A read that is not proved is master's C. The generated C changes by the new name and nothing else: with it mapped back to `sp_poly_index_poly`, each of the 56 corpus programs whose C differs, one of the new tests among them, is master's C byte for byte (208 lines). The new function repeats the 153 lines of `sp_poly_index_poly`, so a later change to that read belongs in both; `lib/spinel_rt.h` only gains lines.

A proved read takes the new function, which the C compiler lays out another way, and that moves loops both ways. By callgrind over fifty-eight loops of boxed reads, instructions a loop pass on master and here: with gcc none costs half an instruction a pass more and twenty-two cost less (by 1 to 22); with clang eighteen cost more (by 1 to 10) and four less (by 2 to 6). The dearest with clang: a Symbol-keyed boxed Hash missed twice by a boxed Float key 350 and 360 (299 and 277 with gcc); a boxed Symbol read by a boxed Integer 567 and 573 (526 and 525 with gcc); a boxed Symbol read by an Integer and a Symbol-keyed boxed Hash missed by a boxed Float key 718 and 723 (693 and 681 with gcc). A read that is not proved runs what it ran, with both: five loops of such reads count the same there and here.

The compiler runs up to 0.38% more instructions on files of 1,000 and of 2,000 such reads (a global, a local or a Hash's element read by a constant, by a sequence, by an element; the least moved by under 0.01%), and its count on optcarrot is within 0.01% of master's.

Of 994 programs that read a boxed value of every kind through an index of every kind, 245 compile to master's C. Of the other 749, 52 are cured and none that was right is lost: 466 are right there and here, and 231 print the same wrong bytes on both. Of 1,360 that read a global, an instance variable or a class variable whose index assigns it (in a sequence, through a method called there, in a call) or does not, 1,320 compile to master's C; of the other 40, 10 are cured, 12 are right on both and 18 print the same wrong bytes. And of 1,004 reads under twenty kinds of receiver, by forty-nine indexes that assign the receiver or do not (a block run in line, a `case`, a `begin`, a sequence, a rescue, a loop) and twenty-four whose receiver assigns the index's variable, 972 print master's line with gcc, and the 32 plain reads of the two shapes are cured. None that was right is lost.

Not here, each as on master:

- a receiver that is not one of the two shapes: `g["n"][g["k"]]`, two reads of a typed Hash, still reads bit 0, for a Hash read can run a default block; so does a receiver that a method answers, `cur[k]`;
- a bare global, instance variable or class variable, or a local a proc shares, whose index is not on the list: bit 0 stays where such an index calls a method, runs a block or writes a global, `$x[(s << "1"; f)]`;
- a read whose index holds a literal `nil`, `true` or `false`, whatever its receiver: `x[nil]` reads bit 0 (CRuby: TypeError);
- a program that may load a file the compiler did not read (a `load`, an `autoload`, a `require` it cannot resolve, a write of the load path; the words are counted in the program's text, so one in a String or in a comment is enough), one with a def or a Symbol named `[]`, `begin`, `to_int`, `to_i`, `respond_to?`, `respond_to_missing?` or `method_missing` or a site that names a method by value, one that reopens a builtin exception class, and one in which the analysis decides a test for this engine, also where the arm it keeps is the one CRuby takes: every read of such a program answers as on master;
- every other caller of `sp_poly_index_poly`: the read of `x[k] ||= v`; a `method(:[])` object, called, indexed, passed as a block or held in a variable. `slice` and `values_at` in a program with one of its own, and `dig` by splatted keys, still answer from bit 0 where CRuby refuses an Integer;
- an index of another kind: an Array, a Hash, a Proc, a String Range, a Class, a Module or an object of a user class still reads bit 0 (CRuby: a TypeError, worded by a `to_s` it asks the index's class; for an object, what its `to_int` answers), a Float Range reads bit 0 where CRuby reads the bit field of its ends cut to Integers, and a String or a Symbol index raises NoMethodError where CRuby raises TypeError, in another function;
- a typed Integer read by a boxed Bignum still reads bit 0;
- an Integer of 2^62 and above is a word here and a Bignum in CRuby, which refuses a Rational past a word (RangeError): such a read takes the far rule, the receiver's sign above its bits and 0 below, where master answered bit 0;
- a program that changes what a builtin exception class does when it is raised or rescued by a road master's own `raise` does not take (`class TypeError < StandardError`, which `any_exc_reopen` does not count; a `===` given to `Module`): the TypeError raised here prints what a `raise TypeError` written at that place prints on master, where CRuby's line can be the one bit 0 printed;
- a value that master hands on out of order: in `t = $w[begin; $w = v; "k"; end]` master reads `$w` after its index, so `t` holds what `v` holds, there and here, and `t[k]` then reads that value's bit `k`, where it read bit 0. The same holds for a `require` elsewhere in the statement of a read, `p [$x[f], require_relative("w")]`: master runs the file ahead of the whole statement, so where the file assigns `$x` the read is of the value the file left, there and here.
