Refuse a kept result of the String mutators that answer self without a bang

`r = s.concat("x", "y"); r << "!"; p s` printed "abxy" where CRuby prints
"abxy!". bytesplice, append_as_bytes, and concat or prepend with other
than one argument answer their receiver, but no alias walk follows them,
so the name that keeps the result holds a copy, and the bang-result
route of refuse_string_alias_copies asked only names ending in `!`.

sa_bang_receiver now takes those four calls. The route refuses the kept
result when it is mutated in place through a local or a global and the
receiver is read, in a sentence of its own, and the returned-parameter
route refuses a method that answers its parameter through one of them
(`def patch(x) = x.bytesplice(0, 1, "Z")`). An instance variable is left
alone: where the call builds it takes the handle itself
(`@r = @s.concat(a, b)`). Under --share-strings the bang route's site is
left alone too: the rule names every such result a shared handle, a
read-only one as well, and the kept result is still a copy there.
