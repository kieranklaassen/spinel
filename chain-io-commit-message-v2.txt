A module the superclass includes is not included again

    module Plus
      def count
        super + 1
      end
    end
    class Root
      def count
        1
      end
    end
    class Parent < Root
      include Plus
    end
    class Child < Parent
      include Plus
    end
    p Child.new.count

printed 3 where CRuby prints 2. Parent has Plus in its chain, so Child
has it too, once, behind Parent, and the `include` in Child adds
nothing. The module's methods were copied into Child all the same, in
front of the copies Parent holds, and Plus#count ran once for each
copy. A third class down it ran three times; a block the module's
method gives to super ran in each copy.

Where a superclass includes the module by the time the class's own
include is reached, directly or through a module that includes it,
process_include_body no longer copies a method of it that calls super
and asks nothing of its receiver: no instance variable, no self, no
call without a receiver. Such a method runs the same in the copy the
superclass holds. Every other method is copied as before, because the
copy is typed by the class's own methods: a module's `walk` over an
`each_item` the subclass overrides needs it. A method that calls super
and does ask its receiver something still runs once for each copy.

The class still records the module, so is_a?, include? and
`rescue Plus` answer as before. Where the class includes the module
first and its superclass is reopened to include it later, CRuby has
the module in the chain twice, and so does this.
