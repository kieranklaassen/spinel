An exception message that begins with the counted form's marker keeps its bytes

    m = "\xFF\xFECM\xFD\x01AAAA rest".b
    begin
      raise m
    rescue => e
      p e.message.bytesize
    end

printed 1094795585 where CRuby prints 15: the message that came back was
a gigabyte of whatever followed the String in memory. With "ab" after
the six bytes it was 25,185 bytes, and with nothing after them it came
back empty.

A message that holds a NUL travels as a counted message: six marker
bytes, the payload's length, the payload. Every reader took a message
for a counted one by the six bytes alone, so a String of the program
that begins with them had its next four bytes read as a length.

sp_cmsg_p now also asks the string for its own length, which for a
counted message is the header's plus the payload's. It reads that
length only once the six bytes match, and only a String, with its own
header, has them. A String that is such a message byte for byte is
given as the payload of a counted one, as a String with a NUL is, so it
comes back whole too.
