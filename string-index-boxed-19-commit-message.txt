String#[] takes a String, Range or Regexp index known only at run time

    g = { "k" => "ab", "r" => (1..2), "x" => /a./ }
    s = "cabab"
    p s[g["k"]]

raised TypeError (no implicit conversion of String into Integer);
CRuby prints "ab". s[g["r"]] and s.slice(g["x"]) raised it for the
Range and the Regexp. The String arms of [] and slice pick the read by
the index's static type; a boxed index matched none of them and went
to the last arm, the character read, whose Integer conversion raises
for all three. A boxed receiver with the same index answered already,
through sp_poly_index_poly.

A boxed index now has its own arm, which calls sp_str_aref_poly. An
Integer is the character read as before. A String is searched for, and
the answer is a copy of it, a new String as CRuby's is; one the
program appends to is boxed as its shared handle, whose buffer moves
as it grows. A Range and a Regexp go to sp_poly_index_poly's arms for
a String receiver, so a Regexp sets the match variables as it does
there. Anything else is converted by sp_poly_arg_int_chk as it was,
and the conversion is counted as emit_int_expr counts it. A Symbol
receiver reads its name through the same arm.
