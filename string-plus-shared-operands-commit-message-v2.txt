The sum of two shared Strings holds one copy while the other is made

    s = +"abc"; a = s; a << "x"
    t = +"def"; b = t; b << "y"
    r = s + t

in a loop that keeps other Strings answered "abcxabcx" on some turns,
and "defydefy" built with clang; CRuby answers "abcxdefy". A String
another name appends to in place is read by copying it. The + arm
bound its operands to rooted temporaries only where the node table
shows an allocation, which a bare read does not, so both copies sat
in one C call: a collection that fell on the second freed the first,
and the second took its slot.

The arm now does so as well when one operand ends in such a read and
the other makes a copy too (str_plus_operand_copy). An operand ends in
such a read when it is the read itself, as operand_may_allocate
answers it for ==; an assignment to such a variable, whose value is
read back out of it ((x = s) + (y = t)); or a parenthesised sequence
whose last statement is one of those. The other operand may also be
an assignment of such a read to a plain variable. One shared operand
beside a plain String keeps its C: sp_str_plus roots its arguments
across its own allocation. So does an operand that ran ahead into a
rooted temporary (arg_ran_first), as the receiver of s&.+(t) has.
