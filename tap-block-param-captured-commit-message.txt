A tap or then block's parameter captured by a closure is the receiver

    class Bag
      def initialize(a) = @a = a
      def each = @a.each { |v| yield v }
    end
    bag = Bag.new([1, 2])
    p [].tap { |acc| bag.each { |v| acc << v } }
    s = "q".dup
    s.tap { |b| bag.each { |v| b << v.to_s } }
    p s

printed [] and "q" where CRuby prints [1, 2] and "q12", and
{}.tap { |m| bag.each { |v| m[v] = v * 10 } } raised "no implicit
conversion of nil into String".

A block whose parameter is captured by a proc made inside it (a lambda,
or a block handed to a method the program defines with yield) has its
body wrapped in an immediately-called lambda, so that each iteration
captures a fresh cell. tap and then run their block once, and the
wrapper's parameter was a copy of the receiver: a String changed
through it kept its old value, an empty Array literal's parameter
settled as an Integer and `acc << v` became a shift, an empty Hash
literal's had no type.

The block of a tap, then or yield_self is left unwrapped when the
receiver is a local variable, a Hash literal or an Array literal: an
empty Array literal only where the tap's value is read and the block
holds no proc literal of the program's own, which is where the inline
emitters type its cell. A captured parameter lives in a cell of its
declared type, so where that is boxed over a typed receiver the
receiver is boxed into it instead of shadowed.

A class of the program that defines tap or then keeps the wrap, and so
does every other receiver: a String out of a call or an instance
variable is still a copy there (`"a".dup.tap { |b| bag.each { b << "x" } }`
answers "a"), which is not part of this change.
