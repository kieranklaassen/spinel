A mutator on a nil String attribute raises NoMethodError

    class Note
      attr_accessor :text
      def initialize; @text = +"ab"; end
    end
    n = Note.new
    n.text = nil
    n.text.upcase!

died with SIGSEGV, and `n.text << "c"` did nothing; CRuby raises
NoMethodError, as an Array attribute does here. A String slot a mutator
reaches through its reader is an sp_String handle and the reader's call
is typed TY_STRBUF: nf_call (analyze_nil.c) kept no nil fact for it,
and cplan_nil gave a handle a call renders no nil target, since the
target binds its receiver as a value. An attribute reader's call on
self, a local or another such reader now carries its ivar's fact where
it is the receiver of a call whose arguments run no code, and its nil
target tests the handle in the slot, as a local's handle is tested. The
source rule is unchanged: a nil the program writes into a slot
initialize sets.

The fix applies where no argument of the call can run code: each is a
literal or a plain read (a local, an instance variable, self, a
constant the program has set) and the call has no block. The slot is
tested, and read again by the call, behind the arguments, and CRuby
takes the receiver ahead of them: after an argument that rebinds the
attribute (`n.text << n.swap`) the call still acts on the String the
reader gave first. A call with any other argument, and a reader's
handle used any other way than as a receiver, compile as before.
