## What this changes

Fix with a cost in a program that holds an appended String: 1 to 8 instructions on a membership call of a String Range with a boxed argument that is a plain String or an Integer (the table below); where the argument is the appended String itself the call now compares it, which master did not: 212 / 162 instructions a call for `cover?` (209 to 210 / 160 to 161 with `--share-strings`), and `include?` walks the Range for it, as CRuby does (2,589 / 2,577 a call over `("aa".."ad")`); with `--share-strings` 9 to 16 more for the appended String where the argument or an end of a Range written there holds a call (a method's value, an Array's element, a reader's field), nothing more for a variable's Range or one written there of variables or plain literals, asked with a variable. A program that holds none compiles to the same C, with `--share-strings` and without.

```ruby
h = {"k" => "a".dup, "n" => 1}
h["k"] << "b"
r = ("aa".."az")
p r.cover?(h["k"])
p r.include?(h["k"])
p r.member?(h["k"])
```

prints `false` three times (`spinel diff`: output-diff), with and without `--share-strings`. CRuby prints `true` three times.

A String something appends to is held as its shared handle, and a boxed read of it carries the handle (`SP_BUILTIN_STRBUF`), not a plain boxed String. `emit_range_call` wrote the membership of a typed String Range with a boxed argument as `_a.tag == SP_TAG_STR && sp_srange_cover(...)`, so the handle was no member. A Hash with one element the program appends to holds every String it was built with as a handle: with `"p" => "ab"` beside `"k"`, `r.cover?(h["p"])` was false too.

The handle is now asked after the plain String: `include?` walks to its text, `cover?` compares it by its bytes, out of line. A nil stored among handles is a box with no handle and is no member. With `--share-strings` a Range a variable holds is read as a copy of each end, made before the argument (`sp_srange_live`), and nothing holds those copies while the argument's call allocates; a Struct member's or a reader's Range hands on the copies it was made with. So the handle is compared with the ends read again from the Strings the Range keeps, once the argument is there (`sp_srange_ends_now`): no copy is made, and nothing allocates between that read and the compare. Where no call can run between those copies and the compare, the copies are the ends still and are compared as they are, with no second read: the Range is a variable's read, or is written there with two ends that are each a variable's read or a plain String literal, and the argument is a variable's read (a local, an instance variable, a class variable, a constant, `self`). Any other argument (an index `arr[0]`, a reader's field `o.v`, an operator, any call) and a Range written there with an end that holds a call read the ends again: a call can run the program's own code, which can change an end. One helper asks that of the argument and of the two ends (`operand_holds_no_call`); that a read is live is `emit_expr`'s own test, now one helper both call (`srange_live_read`). The plain String's line is master's, as it was.

The arm is written only where a box tagged as a handle is known to hold one. `program_strbuf_boxes` answers that once for the program, before any C is written. Master's C stays, byte for byte, in a program that holds no handle, built with `--share-strings` or without; in one that stores, where a handle is wanted, the String of a method call on an object of the program's that is no read of a handle's slot through a receiver (the scan does not follow what such a call renders, so it does not say what that box holds); and in a program that has, or may have, a method of the call's name or a `<=>`, an `==` or a `succ` of its own, in any class: this call does not ask them, before or after. `include?` and `member?` stand aside for four names more, a `to_int`, a `method_missing`, a `<=` or a `<` (below).

"May have" is asked of two tables. A `def` in the builtin's class is in the class table. The rest is `an_prog_never_gives`, the analysis's walk of the program as written (src/analyze.c). It reads the program ahead of every rewrite and of the arm a test of the engine drops: no `def` and no Symbol of the name anywhere, and no site where a method is named, made, mixed in or loaded by something the text does not spell. So `alias <=> index`, `def lo.<=>`, a `String.define_method(:<=>) { }` under a `rescue`, a `send(name)`, an `eval` and a file the compiler did not read leave master's C. So does `class String; prepend Kernel; end`: Kernel's `<=>` answers nil for two Strings that differ, and no text of the program's holds it.

The names asked are the ones CRuby asks, call by call. `cover?` asks its own and `<=>` of the ends; `===` is not asked here. `include?` and `member?` ask their own, then each end for `to_int`, which a `def` in String or anywhere above it, an `alias`, a made method or a `method_missing` can answer; an end that answers an Integer makes the call `cover?` by the compare. Otherwise CRuby walks: nothing more for two one-character ASCII ends, `==` for two all-digit ends that fit a machine word, `Integer#<=` (`#<` for a Range without its end), `Integer#succ` and `==` for all-digit ends past one, `String#succ` and `==` for any other. That is ten names with the three calls' own: `<=>`, `==`, `succ`, `to_int`, `method_missing`, `<=` and `<`; `eql?` is not one. The runtime's walk asks none of them, so `include?` and `member?` keep master's C where the program may give any class a `to_int`, a `method_missing`, a `<=` or a `<`; `cover?` does not ask those four and takes the arm there. The walk does not ask where a `def` lands, so a `def ==` in a class of the program's own leaves master's C too, and so does the Symbol `:==` written anywhere: the three calls answer `false` there, as on master. Of the 6,972 programs of test/, benchmark/ and the packages' tests the two tables answer "may" for 1,266 on `cover?`, 1,307 on `include?` and 1,302 on `member?`, for 1,179 of them by a site. A package is the program's text to the walk: each of the nine tried (set, csv, uri, bigdecimal, pathname, stringio, json, strscan and Gem::Version) leaves master's C.
