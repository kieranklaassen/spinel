gsub with no block roots its Enumerator while its label is made

    s = "ab" * 60_000
    e = s.gsub(/b/)
    t = []
    2_000.times { |i| t << "junk" + i.to_s }
    p e.inspect[-14..]

prints "abab\":junk100>" in a plain run where CRuby prints
"ab\":gsub(/b/)>", and p "a1b2".gsub(/\d/).to_a aborts under
SPINEL_GC_STRESS=2.

The emitted C made the Enumerator and its label, "gsub(/b/)", as two
arguments of one call to sp_enum_with_src. Each is a fresh allocation
held in no root while the other is made, in whichever order the C
compiler evaluates the arguments.

The Enumerator is now made first, into a rooted temporary, and the
label after it. That also settles the order for a pattern that is
neither a String nor a Regexp: it raises TypeError before its inspect
is asked for the label, as it did when built with clang; built with
gcc, inspect ran first.

The root costs 10 instructions for each Enumerator made (callgrind,
100,000 calls: "a1b2".gsub(/\d/).to_a goes from 4,949 to 4,959 a
call). The match is not touched: nothing sets $~ that did not set it
before.

Test: test/gsub_enumerator_rooted.rb, in GC_STRESS_TESTS. Without the
change it aborts at level 2.
