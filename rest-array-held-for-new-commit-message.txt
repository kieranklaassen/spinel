A rest array handed to new is held while the object is allocated

A method roots its parameters before it allocates, so a call may hand
it a fresh value with nothing else holding it. A rest is written so
when no argument lands in it and when a splat fills it:

    sp_Bag_new(sp_PolyArray_new())
    sp_Bag_new(sp_PolyArray_dup(_t6))

The constructor is the one function that allocated first: sp_Bag_new
made the object and then called initialize, whose root of the rest
came after. A collection at that allocation freed the array, and the
object kept whatever took its place. Of 100,000 objects kept in a list
four are wrong in a plain run, for `Bag.new` and for `Bag.new(*xs)`
alike; under SPINEL_GC_STRESS=2 one `new` is enough to abort.

The constructor now roots the rest parameter ahead of the allocation,
as the Struct constructor above it roots its reference arguments, when
it hands the rest on, to initialize or to the clone a proc drives; one
whose initialize is inlined at the call is called with no rest and
stays as it was. The `) {` each allocation arm printed moves ahead of
the arms, so the root comes first in all four: the pooled object, the
two exception layouts and the Array subclass.

A constructor with no rest parameter is the C it was.
