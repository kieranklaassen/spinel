An attribute of an exception class with no initialize is kept once set

    class Tagged < StandardError; attr_accessor :tag, :at; end
    kept = []
    60.times do |i|
      s = +"m"
      s << i.to_s
      begin
        raise Tagged, s
      rescue Tagged => e
        e.tag = "tag-#{i}"
        e.at = [i, "a#{i}"]
        kept << e
      end
    end
    # --share-strings: 59 of the 60 read back wrong; CRuby: none

A class of the program's under a builtin exception, with ivars and no
initialize in its chain, has no constructor on its path, so the runtime
builds it. With --share-strings a raise whose message is a String the
program appends to builds the exception at the raise, to hold that
String ("An exception holds a shared String message as its handle"),
and builds it as a plain exception of the base size: the arm typed to
the class wrote its ivars past the end, in a plain run. Before that
change the arm built it itself, at the class's size.

Without the flag the same class was written past its end once an arm
that names no class of the program had caught it. sp_exc_new_for_catch
built it at the base size there too, and a method of the class called
on the kept value stored its ivars beyond the object:

    class Marked < StandardError
      attr_reader :a, :b, :c
      def mark!(a, b, c)
        @a = a; @b = b; @c = c
      end
    end
    kept = []
    5.times do |i|
      begin
        raise Marked, "a#{i}"
      rescue StandardError => e
        kept << e
      end
    end
    kept.each do |v|
      next unless v.respond_to?(:mark!)
      v.mark!("1" + v.message, "2" + v.message, "3" + v.message)
    end
    n = 0
    100_000.times { |i| n += "x#{i}".size }
    p n               # segmentation fault; CRuby: 588890

An arm typed to its parent, where the parent is such a class too, built
it at the parent's size, and the ivars the subclass adds were written
past that.

A begin with an ensure holds an exception that leaves through its
rescue clauses, raised in a clause or matched by none, as its object
until the ensure has run ("An ensure runs when the exception leaves
through the rescue clauses"), and built it with sp_exc_new_for_catch
too. Raised in a clause and caught afterwards by an arm typed to the
class, 29 of 30 read back wrong, without the flag.

Built by `.new`, or by the rescue that catches a raise by its name, it
had its own size, but sp_exc_new_sub_sized gave it the base exception's
scan:

    class ParseError < StandardError; attr_accessor :line, :ctx; end
    rows = ->(n) { (0...n).map { |i| [i, "r#{i}"] } }
    e = ParseError.new("m")
    e.ctx = rows.(3)
    20000.times { rows.(3) }
    p e.ctx           # [1, "r1"]; CRuby: the three rows

An ivar the program stored was never marked, and its value was freed
under the exception in a plain run.

One builder cures both. sp_exc_new_sub_ivars takes the class's own
scan. The rescue has to know which class was raised, and all it holds
is the name. The names of these classes stand in one table of the
generated code (sp_xbn_name), and that code passes a class's row where
it raises the class or builds it; the rescue then knows the class by
one range test on the pointer (sp_exc_own_by_name), whatever the number
of classes and the length of their names, and sp_user_exc_parent is not
asked a second time. A raise that builds the exception itself, and the
ensure that holds one, ask the same entry (sp_exc_catch_own). A name
that is no row is built as it was.

Where sp_exc_new_for_catch built such a class before, a message given
as a frozen literal stays frozen (`e.message.frozen?`,
`e.message << "x"` raising FrozenError): sp_exc_new_sub_caught is the
same builder with that function's own test of the message.

Cost, in instructions under callgrind for one exception built (gcc,
glibc): 4 where master built the class at its own size (`.new`, the
arm that names it), for one more argument; 27 where an arm typed to a
parent of the same kind catches a subclass raised by name, which is
built as itself now; 5 for a builtin exception caught in a program
that has such a class; and an arm that names no class of the program
builds such a class in 147 fewer. Around these, glibc's strcmp counts
22 to 66 more for the same compares (17,400,000 calls in 150,000 turns
either way): the class's name is a row of the table and no longer the
literal, and strcmp enters by its page-crossing path by the two
addresses' offsets in their pages. Compiling a program that only
defines such classes runs about 18,000 more instructions a class: 1.5%
more at 300 of them, 0.4% at 2,000. A class with an ivar that is no
such class is asked once what it is: 191 instructions for one that is
no exception, 1,149 for an exception class with an initialize of its
own. A program with no class of its own compiles as it did, to within
184 instructions and glibc's string compares.

A program without such a class emits the C it did.
sp_exc_new_for_catch does not change, and sp_exc_new_sub_sized stays,
with the base scan, for a class with an initialize of its own, whose C
does not change either. A builtin exception the program reopens is not
such a class.

Not here: an attribute nothing has stored. The struct is zeroed, as it
was, and zero is not nil in every slot: one the compiler types as an
Integer or as a boxed value reads 0 until it is stored, where CRuby
reads nil. `p ParseError.new("m").line` prints 0 before this change
and after it.
Where the object was built at the base size that read went past its end
and printed what lay there; it reads the object's own zeroed slot now,
and a program that crashed ahead of such a read reaches it. Seeding nil
is a change of its own: CRuby runs methods of the program that the
compiler does not (an `inherited` hook, a `to_ary`), and where one of
them stores a zero the zeroed slot is CRuby's answer.

Nor a class read off a value (`raise x.class, "re"`). Its name reaches
the raise as a copy (sp_exc_class_name), which is no row: no initialize
runs for it, and a class without one is still built at the base size.
And a subclass caught by an arm typed to a parent that has a method of
its own and no attribute, or by a bare arm typed to the parent, is
still built at the parent's size, as before: ivars a method of the
subclass stores go past the object.
