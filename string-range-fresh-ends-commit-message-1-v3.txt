The two ends of a String Range made on the spot are both kept, and made in order

    bad = 0
    3000000.times { |i| m = (i.to_s..(i + 3).to_s).max; bad += 1 if m != (i + 3).to_s }
    p bad             # 18 in CRuby (("7".."10").max is nil), 346 here with gcc
    p (lo..hi).to_a   # lo and hi each print their name: lo, hi in CRuby; hi, lo here with gcc

The two ends were sibling arguments of one C call. Nothing held the end
made first while the other was made, so a collection in between freed it,
and gcc makes the last argument first.

The begin now goes into a rooted temp ahead of the end, when both ends are
made on the spot. An end that is a literal or a read of a variable or a
constant is nothing to collect or to order, so a Range of such ends
compiles to the C it did.

Not here: the Range is held while it is made, not while it is read. One
whose end is made on the spot, read by a method whose own argument
allocates (`("100"..(i + 3).to_s).include?((i + 1).to_s)`), can still
lose that end under SPINEL_GC_STRESS=2. The ends of an Integer or a
Float Range still run in the C compiler's order.
