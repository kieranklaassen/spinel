A Struct's super takes each write barrier after its argument is built

`super(a, b)` in a Struct's own initialize sets the members in one C
comma expression. Inside an expression the barrier pass can only wrap
the holder, `SP_WBO(self)->iv_tags = sp_tags_of(lv_i)`, so with gcc
the barrier ran before the argument was built. A collection inside
the argument promotes the Struct and starts the remembered set over;
the store then lands unrecorded, and the next minor mark frees the
young value in its slot:

    Pair = Struct.new(:name, :tags) do
      def initialize(i)
        super("n#{i}", tags_of(i))
      end
    end

Of 300 of these, with a tags_of that allocates before it answers, 37
read back another value in a plain run built with gcc. clang builds
the argument first and is right. It is the hazard the comment in
gc_wb_insert_seg describes for a statement and leaves open for a
store inside a larger expression.

A store whose argument may allocate (operand_may_allocate), into a
member that holds a reference, is now written as a statement of its
own inside the comma expression, `({ self->iv_tags = ...; 0; })`,
where the pass puts the barrier after the store. Every other store of
a super, and every super with no such argument, is emitted as before.
