chomp cuts a separator that begins with a NUL byte

`"PATH=/bin\0".chomp("\0")` answered the String unchanged, and
`"a\n".chomp("\0")` answered "a": sp_str_chomp_sep took a separator
whose first byte is NUL for the empty one, which strips trailing
newlines. The separator is the empty one when its byte length is 0.
chomp! rides the same function.

----
scan with a String pattern finds it by bytes

`"a\0b".scan("b")` answered [] and `"x,a\0b".scan("a\0b")[0].bytesize`
was 1: sp_str_scan measured the pattern by strlen and searched with
strstr, which ends at the subject's first NUL byte. sp_str_scan_at,
the turn of a block that reads `$~`, did the same.

Both read byte lengths and search with sp_str_find. One byte is found
by memchr. A longer pattern without a NUL is still found by strstr;
when strstr finds nothing, sp_str_find_rest looks behind the NUL it
ended at, by sp_bytestr, as it does from the start for a pattern that
holds a NUL. A pattern without one cannot lie across that NUL, so
nothing is missed, and a subject without one is searched as before,
with one strlen more when a pattern of two bytes or more is not found.
The empty pattern walks to the byte length too.

gsub and sub with a Hash read their Strings by bytes

`"a\0b".gsub(/[ab]/, "a" => "1", "b" => "2").bytesize` was 1: the four
functions behind gsub and sub with a Hash measured the subject and the
replacement by strlen, so the answer ended at the first NUL byte of
either. The pair for a String pattern also searched with strstr, and
answered a String whose length was never set.

They read byte lengths, and the String pattern is found by
sp_str_find. A Regexp's match that holds a NUL byte is looked up as a
String of its own, since the transient key is read as a C string:
`"a\0b".gsub(/\0/, "\0" => "N")` is "aNb".

sub and gsub with a block keep the subject's tail past a NUL byte

`"a\0b".gsub(/a/) { "q" }.bytesize` was 1. Once a match is behind it,
what is left of the subject is appended from inside the String, where
sp_String_append_bin finds no header to measure it by and takes it to
end at its first NUL byte. The emitted loop holds the subject's byte
length and where it stands, so the rest goes in by that count
(sp_String_append_n). sub! and gsub! ride the same loop.
