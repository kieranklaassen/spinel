cover?, === and max of a String Range compare the whole String

sp_srange_cover compared with strcmp, which stops at a NUL byte, so
every String that shares an end's bytes up to one compared equal to
that end: ("a\0b".."a\0c") covered "a\0a" and "a\0d". === and a when
over a Range held in a value ride it. sp_srange_max_v had the same
compare, and so had its walk for the greatest member of an excluded
end: ("a\0b".."a\0a").max answered the end where CRuby answers nil.

cover? and max compare as strcmp did, and by the bytes alone past a
NUL where strcmp finds no difference. A difference strcmp does find
stands as it is, NUL being the least byte, so the common path is
strcmp and a branch, and nothing more is kept across the call than
before: the compare past a NUL is reached by a jump to a function
with the same arguments, which is why two helpers are not static.

The walk for the greatest member compares past a NUL only where it is
CRuby's walk and a member can hold one: the begin holds a NUL, both
ends are 7-bit and the begin has a letter or a digit, so succ steps
letters and digits alone. That is asked once, before the walk. Any
other walk is compared with strcmp as before: ("\0\x7f"..."\x01\0")
holds 66 members here and one in CRuby, and strcmp, which takes them
all for equal, answers the first, CRuby's answer. The walk for the
least member, which Enumerable#to_h of a boxed Range asks for, is as it
was.
