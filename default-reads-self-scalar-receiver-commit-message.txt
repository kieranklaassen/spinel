A default that reads self runs on a String, Symbol, Range or Float receiver

    class String
      def note(k = self + "!") = "n #{k}"
      def ask(s) = s.note
    end
    puts "x".ask("abc")

printed "n x!" for "n abc!": the default ran on the caller's self.
From another class's method, or from the top level where there is no
self, the C did not build.

"A builtin method's default that reads an ivar runs on its receiver"
holds the receiver in a rooted temp and lets the default read it
(emit_reopen_recv_args), in the arms for Random, Array, Hash and a call
with a block. The site at the top of emit_call_body that takes a
String, Symbol, Range or Float receiver without a block still wrote the
default where the call stands. It now calls emit_reopen_recv_args where
the method is the receiver class's own: a def in the class, or in a
module it includes. A method the class only inherits (Object's,
Kernel's) is emitted as before, the receiver and the arguments in
order. The site takes self in a method added to Integer too, so
`def me = note` there no longer fails to build.

A held String, Symbol, Float, Range or Time is the value itself, not a
boxed one: `self.class` in such a default is answered from its type,
where it was handed to sp_poly_class_val and did not build.

Test: test/reopen_default_reads_receiver.rb.
