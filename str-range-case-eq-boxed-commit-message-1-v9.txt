=== of a String Range covers a boxed String

    h = {"k" => "ab", "n" => 5}
    r = ("aa".."az")
    p r === h["k"]
    p ["c", 5, "q", nil].select { |e| ("a".."m") === e }

printed `false` and `[]`; CRuby prints `true` and `["c"]`.

`===` of a receiver that compares by value (a number, a String, a
boolean, a Symbol) with a boxed argument is written as sp_poly_eq of
the two. That arm leaves out an Integer Range and a Float Range, which
cover, by their families 5 and 6 of eq_family; a String Range is family
7 and was not left out, so `("aa".."az") === x` asked whether the Range
equals x. No String does.

The arm leaves 7 out as well, and emit_range_call answers a value that
holds a String: a plain String is covered by its bytes and length, and
so is the text of a shared String handle (an appended String).

With --share-strings a Range a variable holds is read as a copy of each
end (sp_srange_live), and nothing holds those copies while the
argument's call allocates. Where the Range is read so and the argument
cannot give that variable another Range (read_rebound_by, master's own
test), === runs the argument first and reads the Range after it: nothing
runs between that read and the compare, and an end the argument changed
is read as it is. Any other Range, a Struct member's or a reader's, one
written at the === or one the argument may rebind, is read first, as
master reads it. There a String, the plain one and the handle's alike,
is covered by the ends read from the Strings the Range keeps, once the
argument is there (sp_srange_cover_boxed_now), and for a value that
holds no String the temp is rooted before an argument that may allocate,
as master roots a Range no name holds.

Any other value is asked what it was asked, the same sp_poly_eq of the
boxed Range and the value, so no answer changes for a value that holds
no String. One test on the tag sends such a value there. A value the
argument has just made is held while the Range is boxed. Master's
expression holds neither: with both made where the === is written, it
answered `false` for an equal Range at SPINEL_GC_STRESS=2.

Master's C stays where cover? of the Range keeps it (the commit
beneath): in a program that has, or may have, a ===, a <=>, an == or a
succ of its own, in any class (this call does not ask them, before or
after), and in one where that commit does not say what a box tagged as
a handle holds: it stores the String of a method call the scan does
not follow. "May have" is an_prog_never_gives, the walk that commit
asks: a def of the name anywhere, its Symbol, or a site where a method
is named, made, mixed in or loaded by something the text does not
spell; a package's Ruby is the program's text to it. That is one
answer for the program, and srange_eqq_covers_boxed holds it once.

It stays as well at a `===` the compiler's own Ruby asks
(enum_builtin_node). grep and grep_v ask it of each element there, and
this commit does not change them. Over an Array they run as the builtin
does where CRuby calls the grep or walks by the `each` the program gave
it:

    class Array
      def each
        self
      end
    end
    m = ["c", 5, "q", nil]
    p m.grep("a".."m")
    p m.select { |e| ("a".."m") === e }

prints `[]` and `["c"]` in CRuby. Master printed `[]` twice, the first
for another reason, and that one is kept. A method the program itself
names `__enum_...` reads as the compiler's Ruby, and a `===` in it
keeps master's answer too.

Cost (callgrind, 300,000 turns of `n += 1 if r === x`, gcc 13.3 and
clang 18.1). For a String outside the Range a turn runs 86 and 87
instructions fewer: the Range is not boxed for it. For an Integer it
runs 12 and 3 more, the test that tells a String from the rest ahead of
the equality it had. With --share-strings, against this commit without
that: where the argument runs first a turn costs within one instruction
of it for an appended String, a plain String and an Integer held in a
local; with a call's result as the argument, 18 to 21 and 12 more for a
plain String, which is rooted while the Range is read, and 3 to 4 and 1
to 3 fewer for a value that holds no String (21 and 17 more than
master). Where a Struct member holds the Range it is read first: 20 and
23 more a turn for an appended String, 42 to 43 and 24 more for a plain
one, 3 and 6 more for an Integer, and with a call's result 25 and 15 to
18 more for a plain String and 4 and 0 more for a value that holds no
String, the temp's root (28 and 25 to 28 more than master). A Range
written at the === is read first whatever its ends: with two literals 20
and 17 more a turn for an appended String and 33 and 18 more for a plain
one, with two locals 18.5 to 19.25 and 15.5 to 16.25 more and 41.81 and
16.5 to 17.25 more, with two globals 18.5 to 19.25 and 15.5 to 16.25
more for an appended String; an Integer there costs within two
instructions of this commit without that. Each figure was counted in two
orders of the program's lines, the Range's Strings made before the Hash
that holds the appended String and after it, and is the least and the
greatest of the two where they differ; a Range written at the === with
two literals makes no Strings of its own and was counted in the one
order.

Not here: case/when with a boxed subject (the next commit). grep and
grep_v, as above. A boxed String Range equal to the receiver still
answers `true`; CRuby says `false` unless the program gives Range a
to_str or a method_missing. `K === x` for a constant K that holds a
String Range answers false. all?, any? and none? of a String Array with
a String Range answer as if no element matched. An end the other end's
code changes while the Range is written (an append `(a..(a << "z")) ===
x`, a run of statements, a method's or a block's value) is compared as
master's Range holds it wherever master writes the two ends as operands
of one C call, so that which is read first is the C compiler's: the
default build, and --share-strings where master keeps no shared String
for the two ends. Master answers a plain String so; a boxed one, for
which its `false` was CRuby's answer by chance, is now answered so too.
