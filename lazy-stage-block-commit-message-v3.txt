A lazy stage's block answers with its next, has fresh locals and runs a redo

[1, 5, 2, 8, 3].lazy.map { |x| next 0 if x > 3; x * 2 }.to_a answered
[2, 4, 6] where CRuby has [2, 0, 4, 0, 6], [1, 2, 3].lazy.map { |x|
y ||= x; y }.to_a answered [1, 1, 1], and a redo in the block was
refused. emit_lazy_pipeline_expr wrote the block's leading statements
straight into the pipeline's one C loop and read the last one as the
answer: a next was the loop's own continue and dropped the element,
nothing reset the block's locals, and a redo had no label to go to.
Under a begin that next also popped the rescue's frame, as a next that
leaves the begin does, and a raise after the pipeline went uncaught.

A stage now opens its block as the other builtin iterators do, with
emit_iter_step_open, and reads the answer through emit_iter_step_tail or
emit_iter_step_cond, where the step has work for them
(lazy_block_wants_step): a next or a redo of the block's own, or a
local that has to be fresh, which is one a closure holds or one the
block does not assign at its top level before anything names it. Any
other block emits the C it did.

A block with a break anywhere in it, a nested block's or loop's own
included, is read as it was (lazy_block_plain). In the step's frame the
break would leave only the frame, and the stage would go on with nil
where the block raises LocalJumpError; the break of a pipeline written
inside the block has no loop of its own to leave and went the same way.
So in such a block a next still drops the element, the locals are not
reset and a redo is still refused. A redo is also still refused where
the stage would answer wrongly with it: in find_all, which answers nil
here with or without it; in a drop_while block of more than one
parameter, whose branch binds the first alone; and beside a
destructured parameter, which the redo would bind again.

The cost falls on a block with a next or a redo that master ran right,
which now pays the step's frame: map { |x| next 0 if x < 0; x * 2 }
over 200,000 Integers, ten times, goes from 216,204,165 to 222,204,036,
3 instructions an element. A local first assigned under a condition
pays its reset, 4 an element.

docs/limitations.md says where a redo in a lazy stage is still refused,
and the refusal test takes a stage's block that holds a break.

Test: test/lazy_stage_step_frame.rb (expected from CRuby 3.3.6 with
--enable-frozen-string-literal). master refuses it at its first redo
line and, with the three redo lines out, has 17 of the other 28 wrong
and stops before the last 5. test/lazy_stage_break_beside_next.rb,
test/lazy_drop_while_break_beside_next.rb and the four
test/lazy_stage_break_in_*_beside_next.rb hold a break beside a next,
written in the block, in the receiver and an argument of a call that
takes a block, in a for's collection and in a pipeline inside; they
pass on master too.
