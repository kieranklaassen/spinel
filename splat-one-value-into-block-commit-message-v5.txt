One value with no to_a splatted into a yield or a proc arrives as itself

A splat in the argument list built for a yield or a proc's call was
spread with sp_enum_items_from, which has no items for a value that
is no collection. So one value splatted there was dropped:

    def g(v) = yield(*v)
    p(g(5) { |a| a })              # nil; CRuby 5
    f = proc { |a| a }
    x = :k
    p f.call(*x)                   # nil; CRuby :k

CRuby asks to_a only of a value that has one; any other value is the
one argument, itself. emit_spread_args_into now spreads such a splat
with sp_splat_arg_items, a new helper beside sp_enum_items_from: an
Integer (a big one too), a Float, a Symbol, true, false, a class and
an object of a class the program wrote are the value itself.
Everything else goes to sp_enum_items_from as before.

The helper is chosen only in a program with no way to a to_a of its
own, the walk the commits beneath make
(splat_program_may_make_to_a): an Integer has a to_a where the
program reopens Integer, a class where it defines self.to_a. A splat
known to be an Array, a Hash or a Range compiles to the C it had.

An object is handed over only where the commit beneath calls its
class the program's own (splat_class_is_own): a StringIO, a Tempfile
and a Zlib reader keep the list they had. A typed operand is asked
at compile time. For a boxed one the run time reads a table of the
answers per class (sp_splat_own_cls, emitted only into a program
that builds such a list).

The value arrives boxed, and a boxed receiver does not reach every
method the program wrote. A comparison or a unary operator of a
boxed object is the builtin one whatever its class defines
(`t = [K.new, 1]; q = t[0]; q <=> 1` answers 1), and a builtin
class the program reopens answers a boxed receiver with the builtin
method (`q + 2.0` with Float#+ reopened answers 3.5). Where the
value was dropped such a call raised on nil; handing the value over
would make that raise a wrong answer. So an object whose class, a
class above it or a module it includes writes !=, <, <=, >, >=, <=>
or a unary operator keeps the list it had
(splat_class_arrives_boxed), and so does every splat of a program
that reopens Integer, Float, Symbol, TrueClass, FalseClass, NilClass,
Numeric, Comparable, Object, Kernel, Class or Module
(splat_program_reopens_value_class).

A lambda's call and a Method's keep the list they had. Both count
their arguments: with the value dropped they raise ArgumentError,
and in a program whose to_a the compiler cannot see (a skipped
require, a name built at run time) CRuby raises ArgumentError there
too, for the two values the to_a answers. Handing the value over
would make that raise an answer. Which of the two a Proc is, only
the run time knows, so it is asked there (sp_splat_arg_items_of).
`pr.call(*x)` therefore reads its receiver as it builds the list, and
only where a splat may hand a value over: a local or an ivar where
it stands, unless an argument can give it another value
(read_rebound_by: an assignment in the operand, or a call that may
run a proc that assigns it); anything else is run first, as CRuby
runs it, into a rooted temp the list and the call both read. A
lambda passed to a yield with `&` is asked too. A lambda written in
place, a Method and a curried Proc compile to the C they had. So
`lambda { |a| a }.call(*5)` still raises ArgumentError where CRuby
answers 5.

A boxed Array or Hash splatted there ran right before and now pays
the test of what the value is. A Proc's call makes it first, in line
(sp_splat_arg_items_of), and reads the Proc only for a value that
is no builtin's object. Instructions a call (callgrind, 200,000
calls, gcc and clang): `f.call(*v)` with the Proc in a local 9 and
5 (152,473,507 before and 154,274,649 after with gcc), in an ivar 10
and 5, with an operand that runs a method (`f.call(*h.v)`) 9 and 5;
a lambda in a local 9 and 5; `yield(*v)` into a block written at
the call 7 and 6, into `&pr` 9 and 9; `mk.call(*v)`, whose receiver
is a call and takes the temp, 21 and 15. What a boxed value is, is
known only when the program runs, so no list made at compile time
takes the test away.

Not changed: a String. It is dropped there as before. The list is
built of boxed values and a boxed String is a copy, so a block that
appends to its parameter would write to the copy and the caller's
String would stay as it was, where passing the String without the
splat changes it. That wants the String handed over shared, which is
not this change's to decide.

Not changed either: a typed Proc, Regexp, Rational or Encoding and a
builtin exception are still dropped there, and so is an object with
a singleton method or extended by a module (its singleton class is
no class the program opened). `f[*x]`, a splat after or before
another argument and a splat into a method take other paths.

Tests: test/splat_one_value_into_block.rb,
test/splat_one_value_into_block_bigint.rb for a big Integer,
test/splat_package_object_into_block.rb for a StringIO, a Tempfile
and a class of the program beneath one, and
test/splat_proc_receiver_read_once.rb for an operand whose call
writes the local the Proc is read from.
