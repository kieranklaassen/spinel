A class's own send takes a literal first argument

    class Conn
      def send(msg, flags) = "#{msg}:#{flags}"
      def hello(k) = "Conn#hello #{k}"
    end
    puts Conn.new.send("hello", 0)

printed `Conn#hello 0` where CRuby prints `hello:0`, and without the
hello the program was refused (undefined method 'hello' for an instance
of Conn). test/send_literal_and_user.rb says a class that defines its
own send is dispatched normally and is never mistaken for Kernel#send;
that held for a runtime argument only. desugar_public_send_recv and
desugar_implicit_send retargeted the call to the method the literal
names before asking whose send it was.

Now the retarget stands down where the call is proved the program's own
(send_call_owned). The proofs place a def by where it stands in the
text and take self for the object of the def around it, so they are
asked only in a program whose text cannot undo either, tested once for
the program (own_def_takes_call, program_text_listed). A program that
fails keeps the retarget in every call, and its C: one with a require
the parser lifted ahead of its statement or an autoload (the node table
says so: the program node's req_hoisted); an alias of send, __send__ or
public_send, or a def of one that goes on to super, to a method object,
to another of the three or to any method the program defines;
instance_eval, instance_exec, the class_ and module_ forms or
define_method by any spelling; a module with a second body, or an
include, prepend or extend that is not a plain line of a class body, a
module body or the top level; BasicObject.

In a program that passes, the receiver's class has to define the name:
its own def, an inherited or included one, a Struct block's; a class
method for a class named by its constant; the enclosing class's or a
top-level def for self, written or implied. And the receiver is an
object of that class where it stands: self outside the block of a `new`
or a `define` (self_is_scope_object), `K.new(...)`, or a local every
write of which is `K.new(...)` and which is written on every path to
the read (recv_object_class_proved). A receiver that may be nil keeps
the retarget: nil's send is Kernel's, and the method the literal names
raises NoMethodError for nil where the program's method would run with
no self. __send__ and public_send go the same way.

And the method's def has run by the time the call does, as far as the
text tells (own_def_stands_before): it stands in a top-level statement
ahead of the call's, under nothing but class and module bodies; or in
the call's own, with the call inside a def that no statement between
the two can run. A class reopened further down has not given its
instances the name when the call runs, nor has one whose def an `if`
did not reach, nor one whose body calls the method ahead of the def:
Kernel's send is still the call's there.

The call left standing is an ordinary call to the splat check as well.
splat_appended_param took the literal for the method's name whatever
the receiver, so a String splatted into a send that appends to it,
`c.send(:tag, *[$g])`, would have gone over as a copy; it is refused
as it is under any other method name.

Every other receiver (a parameter, an instance variable, a method's
value, an element, a boxed value) is retargeted as before, and a program
that defines none of the three names takes the path it always took: the
corpus's generated C is unchanged. The proofs are asked of every call
of the names in every desugar pass, so the program's text is read once
(proof_text): each node's parent and owner, each statement's place in
its list, the class each local's writes give it; no proof scans a list
again.
